Methodology

Within a campaign

Bars show medians across checked trials. The range shows observed trial minimum and maximum, not a confidence interval. Latency values are medians of trial percentiles, not percentiles of pooled samples. Each case has its own bar scale.

The comparison badge uses the selected baseline within the same case. Higher throughput is better; lower latency, CPU and memory are better. Missing measurements are shown as “—”, never zero.

Workload boundaries

Consumer-only prefill and post-run validation are outside throughput timing. CPU deltas include setup, prefill, validation and teardown; RSS is final, not peak. Mixed cases count a completed publish/consume pair once. Dedup counts unique stored messages. Core-on-stream throughput waits for both durable ACKs and live callbacks.

NATS standalone consumer state can flush asynchronously even with stream sync set to always; the modes do not guarantee equal consumer power-loss behavior. Core forwarding is transient in every mode. NATS sync documentation.

ACK-only latency and full Fetch/ACK cycle latency are labeled per case. Core bulk cases report throughput only. Publisher and subscriber flush barriers bound sends to 1,024-publication windows; throughput includes those barriers. Raw JSON preserves individual trials.

Environment & reproduction
GitHub-hosted runs use shared, unpinned machines; compare cases within one campaign. Different machines and storage can substantially change these numbers.
