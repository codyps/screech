Methodology

Matched results on shared tiles

Each workload tile shows standalone and clustered results together. Each bar is the median of checked trials for one server mode, campaign and publication count. Different message counts and campaigns remain separate bars. Ranges show observed trial minimum and maximum, not confidence intervals. Latency values are medians of trial percentiles, not percentiles of pooled samples. Each tile has its own bar scale.

Automatic comparisons use matching peers: Screech FULL and unsafe ACK compare with NATS always; R3 and R5 compare with the other server at the same replica count. NATS always compares with Screech FULL; NATS deferred-sync modes compare with Screech unsafe ACK. Core compares the two Core servers. Ratios require the same campaign, message count, replication count and latency boundary. Hiding a peer does not change the comparison. A specific baseline can also be selected. Higher throughput is better; lower latency, CPU and memory are better. Missing measurements or peers are shown as “—”, never zero.

Workload boundaries

Consumer-only prefill and post-run validation are outside throughput timing. CPU deltas include setup, prefill, validation and teardown; RSS is final, not peak. Cluster CPU and RSS sum all voters. Voters share the runner’s host and filesystem, so these results do not measure cross-host network latency or independent-disk performance. Mixed cases count a completed publish/consume pair once. Dedup counts unique stored messages. Core-on-stream throughput waits for both durable ACKs and live callbacks.

NATS standalone consumer state can flush asynchronously even with stream sync set to always; the modes do not guarantee equal consumer power-loss behavior. Clustered NATS consumer ACKs and stream retention use separate Raft groups. Final retention/ACK-floor checks allow up to five seconds for convergence outside throughput and latency timing. ACK latency does not measure retention deletion latency. Core forwarding is transient in every mode. NATS sync documentation.

ACK-only latency and full Fetch/ACK cycle latency are labeled per case. Core bulk cases report throughput only. Publisher and subscriber flush barriers bound sends to 1,024-publication windows; throughput includes those barriers. Raw JSON preserves individual trials.

Environment & reproduction
GitHub-hosted runs use shared, unpinned machines; compare cases within one campaign. CI measures standalone, R3 and R5 on separate runners using the same binaries. Paired server ratios share a host; absolute values across campaigns can reflect different CPUs and storage.
